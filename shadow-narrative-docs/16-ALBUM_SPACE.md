# Shadow Narrative — Album Space

本文档定义产品第一屏（斜轴相册）与照片界面的完整规格。

## 1. 空间总览

产品是 7 个体验状态。用户感知上它们是同一个空间的不同状态，不是 7 个页面。

```text
Album（第一屏）
  ├── Library（左侧抽屉，全部照片）
  └── Photo View（点某张照片）
        ├── 原图模式  ⇄  粒子模式
        ├── Conversation（字幕展开）
        └── Journal（用户主动触发）
```

| 空间 | 入口 | 本文档章节 |
|---|---|---|
| Album | 默认 | §2–§5 |
| Library | 左侧抽屉 | §6 |
| Photo View | 点相册里的照片 | §7 |
| 原图 ⇄ 粒子 | Photo View 内 | §8 |
| Conversation | 照片下方 | §9 |
| Journal | 用户主动 | §10 |

## 2. 斜轴相册

### 2.1 它是什么

收藏的照片（`Photo.favorite = true`）沿一条斜轴排列在 3D 空间里，
由近及远向纵深退去。

**不是平铺网格。** 没有行列、没有对齐的格子、没有边界。

### 2.2 几何

```text
轴方向      normalize(0.62, 0.26, -1.0)    向右、向上、向远
起始点      (-0.90, -0.42, 0.55)          第一张的位置
间距        0.55                            沿轴每张递增
```

这些是**起点值，不是定稿** —— 参考视频已丢失（`recon/environment.md`），
视觉方向要靠现场调参收敛。实现时必须提供运行时调节入口。

排布规则：

- 每张照片面向相机（billboard），不做自由朝向
- 进一步的照片更小、更暗、更模糊 —— 构成景深
- **不做**：卡片边框、投影、背景块

### 2.3 缩略图形态：原图为主 + 边缘粒子化

这是用户 2026-10-09 拍板的形式。

| 区域 | 表现 |
|---|---|
| 主体 | 清晰的原图，可辨认 |
| 边缘 | 逐渐碎成沙粒 |

**实现方式**：两层叠加。

```text
下层  贴图四边形（原图），边缘用 alpha 渐隐
上层  该照片的粒子云，密度在边缘处升高
```

不是每张照片一个粒子系统 —— 那是 N 个 draw call 和 N 份显存。
**全部照片的粒子合并进一个 Points 几何体**，一次绘制。

### 2.4 性能：只给焦点附近加粒子

**这是必须守住的约束。**

40 张照片如果每张都有边缘粒子，即使每张只有 2k 粒子也是 8 万，
再叠加主照片的粒子就会越过 Ultra 档预算。

规则：

```text
焦点照片        完整粒子边缘      ~4000
焦点 ± 3 张     减半             ~2000
更远            纯贴图，无粒子    0
```

这样粒子总数被**焦点窗口**限定在约 1.6 万，与照片总数无关。
副作用是它自然产生了景深：远处的照片没有粒子，看起来更"实"、更远。

档位影响见 `15-DEVICE_ADAPTATION.md`；Low / Minimal 档下全部退化为纯贴图。

### 2.5 排序

按 `takenAt` 升序（缺失时用 `createdAt`）。新的在轴的一端。

轴的哪一端是新的、哪一端是旧的，需要在可见处给一个轻量的时间提示 ——
否则用户会迷失在一条不知道往哪走的线上。

## 3. 斜轴的导航

### 3.1 移动

| 输入 | 行为 |
|---|---|
| 拖拽（鼠标 / 单指） | 沿轴移动 |
| 滚轮 / 双指捏合 | 沿轴移动 |
| 方向键 ← → | 逐张移动 |

**不做自由旋转。** 斜轴相册里相机被锁定在轴上，只能前后移动。
自由旋转是 Photo View 里的能力（`06-PARTICLE_ENGINE.md` §15），两者不要混。

理由：相册是"走进去看"，需要一个稳定的方向感；一旦能自由转，
用户会失去"我在往哪走"的判断。

### 3.2 焦点

离相机最近的那张是焦点。

- 焦点照片：略大（约 1.08 倍）、最亮、有边缘粒子
- 相邻照片：递减
- 焦点必须在视觉上无歧义 —— 一次只有一张是焦点

### 3.3 进入

点击焦点照片（或按 Enter）：

```text
1. 相机沿轴推进，焦点照片放大到充满画面     GSAP 时间线
2. 轴上其余照片向两侧淡出
3. 交接给颗粒引擎，进入 Photo View 的原图模式
```

时长与缓动见 §11。

## 4. 空态

没有任何收藏时：

- 不显示空网格、不显示"暂无内容"
- 画面安静，中央一行低存在感的提示：把照片拖进来
- 拖入即上传，上传后**不自动收藏** —— 收藏是用户的决定

## 5. 上传入口

Album 是上传的地方：整页可拖入，也可点击选择。

上传后：

```text
照片立刻出现在轴的末端（原图）
    ↓
后台发给 AI
    ↓
字幕在照片下方浮现
```

**上传不自动进收藏。** 用户要在 Library 里或 Photo View 里主动收藏，
它才会进入斜轴的正题。未上传过任何照片时轴是空的，见 §4。

## 6. Library（侧边抽屉）

### 6.1 位置与形态

- 从**左侧**滑出，宽度 340px
- 复用粒子控制面板那套滑出机制（`07-UI_PAGE_SPECS.md` §3），但从左侧
- 打开时**不加暗色遮罩** —— 斜轴仍然可见

### 6.2 内容

按时间分组的**列表**，不是网格。

```text
2026 · 07
  ─────────────────────────
  ▫  玉龙雪山            ★
  ▫  傍晚的路
  ▫  那碗汤

2026 · 06
  ─────────────────────────
  ▫  ...
```

每行：

- 一个极小的缩略图（约 28px，仅用于辨认，不构成"平铺"）
- 一行文字：`caption` 或 AI 提炼的短标签，都没有时用时间
- 收藏状态（★），点击可切换

### 6.3 交互

- 点某一行 → Photo View
- 行右侧的 ★ → 切换收藏，**不进入**
- 顶部一个搜索框（照片变多之后必须有，否则列表无法用）

## 7. Photo View

### 7.1 布局

沿用 `07-UI_PAGE_SPECS.md` §1 的尺寸表：

```text
照片主体     画面高度 55–65%  ·  水平居中  ·  垂直偏上 4%
日期         照片下 24px  ·  text-meta  ·  opacity 0.55
字幕         日期下 8px   ·  text-title 之外的次级层级
操作区       字幕下 24px
```

**字幕占用原来"标题"的位置。** 原来的标题位置放的是记忆标题，
现在那里放 AI 的第一句话 —— 因为它才是用户最想看到的东西。

### 7.2 操作区

```text
Into this moment  ⇄  返回   从中间扩散，照片变成粒子（主要动作）／回到原图
收藏                  切换 favorite
对话                  展开 Conversation
整理成日志            触发生成
← 返回相册            回 Album
```

第一行的两个动作**占同一格**，交叉淡化（§8.6）—— 同一时刻只显示一个。

**除它以外全部低存在感。** 参考 `07-UI_PAGE_SPECS.md` §1
的透明度量化定义。

按钮文案是用户 2026-10-09 定的，**2026-10-10 由用户改成英文
`Into this moment`**（原先写的是「翻开这一天」）。**不要把它改回 `View Memory →`
之类的功能描述** —— `Into this moment` 是产品语言，它把「切换到粒子模式」
这个技术动作说成了一件关于记忆的事。

用英文与顶栏的 `MEMORY` / `Memories` 一致，而不是与「参数」「设置」那组
工具入口一致 —— 它属于记忆本身，不属于工具。

### 7.3 删除

两步确认，放在左下角，不紧挨主操作。
顺序见 `08-DATA_API_SPEC.md` §16。

## 8. 原图 ⇄ 粒子

### 8.1 两种模式

| 模式 | 表现 |
|---|---|
| **原图** | 真实的照片，清晰，可辨认 |
| **粒子** | 照片由沙粒组成，可拖拽旋转、指针扰动 |

**进入 Photo View 时默认原图。** 由用户主动点「Into this moment」才变成粒子。

理由：先给真实的照片，抽象留到用户主动要的时候。这样粒子的第一次出现
才有分量 —— 如果一进来就是粒子，它会变成背景噪音。

### 8.2 切换的实现：从中间向外扩散，不是淡入淡出

**关键前提：粒子本来就是从照片上采样来的，它的位置就是对应像素的位置。**
所以切换不需要搬运任何东西 —— 只需要让照片**按空间次序消失**，消失的地方粒子接手。

**形态（用户 2026-10-09 定下）：从中间开始。**
图片从中间开始消失，同时粒子从中间开始渲染，向外扩散。

实现是一个**共用**的空间场 `snDissolveField(worldXY, maxR)`：

```text
场的主体是「到中心的半径」，归一化到 0（中心）→ 1（最远角）
四边形      d < uDissolve 处 discard 掉
粒子        d 刚小于 uDissolve 时出现（阈值紧贴波前内侧）
```

`uDissolve` 一个数同时驱动两层，两者严丝合缝互补 —— 不存在对不齐的可能。

**四条必须守住的细节**，任何一条错了都会退回「叠了两张图」：

1. **波前要加噪声扰动**。纯半径会变成一个机械的圆。叠一层 value noise
   （振幅约 0.30），让边界不规则，但整体方向仍然明确是「从中间」
2. **粒子阈值必须紧贴波前内侧，不能居中**。写成
   `smoothstep(d-0.03, d+0.03, ·)` 会让粒子在照片消失**之前**就出现，两者重叠
3. **不能用整体透明度交叉淡入淡出**。照片整体变透明的观感是「照片在消失」，
   不是「照片在碎裂」—— 因为缺少空间上的先后
4. **粒子位置用 `aPositionA` 而不是扰动后的位置**。指针场和呼吸会让粒子
   偏离原位，那样它出现的位置对不上刚消失的那一块

**用世界坐标而不是 UV 算半径**：UV 空间被图片宽高比拉伸，在那里算半径得到的是
椭圆。世界坐标天然等比。

**归一化用勾股而不是 `max(halfW, halfH)`**：波前要扩散到**四角**才算走完，
否则角落会剩一块没溶解的照片。

时间分配见 §11。

### 8.3 自动切换

有些动作必须先切到粒子（用户 2026-10-09 的要求）：

| 动作 | 自动切到 |
|---|---|
| 点「Into this moment」 | 粒子 |
| 进入 Theater / Story | 粒子 |
| 展开 Conversation | 保持当前模式不变 |
| 开始写 Journal | 保持当前模式不变 |

**Conversation 和 Journal 不切模式** —— 它们是读字的场景，
强行切到粒子会伤害可读性。

### 8.4 没有手动切回的入口

**不要加「原图 / 粒子」的切换按钮**（用户 2026-10-09 明确去掉，实现过又删掉）。

理由是：一个**并排的「原图 ⇄ 粒子」开关**把这件事说成了**显示选项**，
而它其实是一次**关于记忆的动作**。开关一放上去，「Into this moment」就退化成了
一个美化过的切换按钮。

> ⚠️ **2026-10-10 澄清：这一条禁的是「并排两个常驻选项」，不是「能回来」。**
> 出口搬进 `Into this moment` 那一格之后（§8.6），外看像是个开关 ——
> 但它不是：同一格里任何时刻只显示得下**一个**动作，原图态写「Into this moment」、
> 粒子态写「返回」，用户没有「选哪个」的余地，所以它读起来还是一次
> 进出的动作，不是两个并列的模式。

进到粒子态之后想回原图，点那一格的「返回」即可（§8.6）；
回相册再重新进入时，自然又是原图（§8.1）。

### 8.5 专注模式：翻开的瞬间相机推近

点「Into this moment」时，相机同时沿视线推近到 `fitDistance × 0.88`。

**幅度刻意小（12%）。** 要的是「主体稍微放大一点」的专注感，
不是推上去 —— 推近了会让人以为要看细节，而粒子态看不了细节。

推近与溶解**共用时长和缓动**，同步完成。

回到照片状态时（离开再进来）相机自然复位到 `fitDistance`，
这条没有特例路径。

### 8.6 返回：出口在「Into this moment」那一格

翻开的动作对应**进入一个新画面**，所以出口是一段文字而不是一个控件。

- 出口**就在「Into this moment」原来的位置**：进去和出来是同一格里的两个动作
- 点返回 → 溶解反向播放 + 相机拉回，回到原图
- 回相册再重新进入时，自然又是原图（§8.1）

> **2026-10-10 改版。** 原先出口在左上角、和 `MEMORY` 叠在同一格交叉淡化。
> 用户的原话是「放左上角交互不顺畅」—— 点进去的按钮在画面正下方，
> 要出来却得跑到屏幕对角去找。**进得去的门就是出得来的门。**
>
> 这一改也让 §8.4 那条更好守：同一格里任何时刻只显示得下**一个**动作
> （原图态是「进入」，粒子态是「回来」），所以它仍然读成一次关于记忆的动作，
> 而不是一个「原图 ⇄ 粒子」的开关。
>
> 附带好处：按钮元素本身没变，点完之后**焦点还在原地** ——
> 上一版要专门做一次焦点交接（`inert` 会把焦点丢回 body），现在不用了。

#### ⚠️ 不能让人感觉是切换页面

用户 2026-10-09 的附加约束。这是本产品最核心的一条主张
（`00-MASTER_README.md` §1：所有状态像**同一个空间的不同状态**），
而一个返回按钮最容易破坏它。三条实现纪律：

1. **不加箭头图标。** `←` 是页面导航的通用符号，一放上去就变成"返回上一页"
2. **复用「Into this moment」完全相同的文字样式**，而不是控件的样式。
   它就是同一位置的一段文字，不是新出现的 chrome
3. **用与溶解同一条缓动和时长（1200ms / `--ease-morph`）交叉淡化**，
   让它成为这个镜头的一部分。用 UI 的 350ms 会让它读成"界面在响应"，
   而不是"空间在变化"

实现上两个动作是**同一格里互相压着的两段 `<span>`**，不是两个按钮 ——
嵌套 `<button>` 会触发 hydration 错，而只换文案则是一瞬间的换字，
读起来像控件跳了一下，不是空间在变。

⚠️ 两段都要标 `aria-hidden`，而且是**相反**的条件。React 对 `aria-*` 传 `false`
会写成 `aria-hidden="false"`（明确暴露）而不是删掉属性 —— 只标一个的话，
另一个会一直露着，读屏器把两个动作一起念成「Into this moment 返回」。

这与「重新进入就是原图」是同一条规则的两种走法，不矛盾：
返回到的是**同一个画面的原图状态**，而重新进入是**从头开始**。

### 8.7 旋转只在粒子模式下开放

**原图模式关闭相机旋转。** 照片是零厚度的平面，转到侧面会变成一条线，
没有任何可看的东西。旋转是粒子模式的能力 —— 粒子有 z 向厚度（`06 §4`），
转起来是块有体积的东西。

用户如果在粒子模式里转歪了，**切回原图时相机会平滑地转回正视角**
（用与模式切换同一条 `--ease-morph`），不是瞬跳。

这条是 2026-10-09 实现 Round 4 时定下的，补进规格。

## 9. Conversation

展开后出现在照片下方，**不跳转到另一个页面**。

- 第一行是字幕，视觉上仍然是字幕的样式，不是气泡
- 之后的对话用极简的文本流，不用气泡框（`02-DESIGN_SYSTEM.md` §14）
- 输入框在底部，低存在感

## 10. Journal

用户主动点"整理成日志"才生成。

生成后以沉浸式阅读状态呈现：宽度 400–600px，大留白，背景粒子极弱
（沿用 `07-UI_PAGE_SPECS.md` §7）。

## 11. 动画编排（GSAP）

### 11.1 职责边界

**GSAP 只负责镜头编排。motion 保留 UI 微交互。**

| 层 | 工具 | 负责 |
|---|---|---|
| 镜头 | **GSAP** | 相机推进、场景切换、跨元素严格时序 |
| 粒子 | 自研 rAF | 粒子位置、morph、指针场 |
| UI | motion | 导航、面板滑出、提示淡入淡出 |

引入 GSAP 的理由：粒子是我自己写的 rAF 循环，**motion 驱动不了它**。
"相册焦点 → 相机推进 → 原图变粒子"这种多阶段镜头需要在同一条时间线上
同时驱动相机位置、shader uniform 和 DOM 透明度，这是 GSAP 时间线的强项。

### 11.2 必须共用同一套缓动

两套动画库并存的风险是动效性格分裂。所以：

**GSAP 的 ease 必须由 `02-DESIGN_SYSTEM.md` §10 的曲线换算而来**，
不直接使用 GSAP 内置的 `power2.out` 这类命名缓动。

```ts
// 换算示例
gsap.registerEase("sn-enter", CustomEase.create("sn-enter", "0.16,1,0.30,1"));
gsap.registerEase("sn-morph", CustomEase.create("sn-morph", "0.65,0,0.35,1"));
```

### 11.3 相册 → 照片的镜头

```text
t=0      用户点击焦点照片
         轴上其余照片开始向两侧淡出 + 轻微向远退

t=0–700  相机沿轴推进到焦点照片前方
         缓动 sn-enter

t=400    焦点照片的贴图四边形开始放大到画面尺寸

t=700    其余照片已不可见（opacity 0）
         交接给颗粒引擎

t=700–   进入 Photo View 的原图模式，可继续操作
```

### 11.4 原图 → 粒子（Into this moment）

```text
t=0       波前出现在画面中心
t=0–1200  uDissolve 0 → 1，波前向外扩散到四角
          同一时刻：四边形在波前之内 discard，粒子在波前之内出现
t=1200    照片完全消失，整个画面由粒子构成
```

时长复用 `--duration-morph`（1200ms），缓动 `--ease-morph`。

**全程没有交叉淡入淡出。** 任何时刻、任何位置，只可能是「照片」或「粒子」
中的一种在显示 —— 这就是它看起来像「解散」而不是「叠图」的根本原因（§8.2）。

### 11.5 时间线 → 照片

> 2026-10-10 补写。§11.3 讲的是斜轴相册那条路（Round 5），
> 而当前唯一的入口是时间线，它走的是同一条镜头的另一种形态。

```text
t=0       用户点中网格里的某张照片
          时间线整层开始退场（opacity → 0，--duration-ui）
          那张照片脱离网格，出现在它原来的位置上

t=0–450   取原图并装进画布（同一张图，走 HTTP 缓存，通常 <100ms）
          终点矩形由引擎报（ParticleSystem.photoScreenRect）

t=400     换路由（不是立刻 —— 见下）

t=450–   照片从格子飞到它在画布里的位置（800ms / sn-enter，同 §11.3）
t=800     画布那一层亮起（飞行过半才开始，早了会叠影）

t=1050    两张图已经重合，飞行的那张淡出
t=1150    日期与字幕淡入（350ms，--duration-ui）
```

日期与字幕的淡入放在**文字层自己**身上（`MemorySpace` 里那个 `absolute z-10`
的 div），放在别处不行：它是正 z-index 的定位后代，永远排在画布之上，
所以它淡自己的，不会掉下去。往上挪一层（`.sn-content` 或 `main`）就会
成为层叠上下文、整块沉到画布底下 —— 而画布有实心底色 ⇒ 文字全没了。
见 `05-TECH_ARCHITECTURE.md` §6.2。

**路由为什么晚 400ms 换。** 立刻换的话，时间线那棵 DOM 会在 ~100ms 内被卸载，
而它才刚开始淡出 —— 会读成一个突兀的弹出。先让它自己退场，走完
§11.3 里 t=0–400 那一段，再换。代价是地址栏晚 400ms 变，换来的是
「同一个空间」的读感。

**飞行的那张图与画布里的那张是同一张。** 同一个 `src`、同一份 HTTP 缓存，
所以首尾两端都能和邻居对上，中间只是位置与大小在变
（圆角在飞行中收掉：格子有圆角，画布里的照片没有）。终点由引擎自己报，
不在外面把 `fillDistance / offsetY / FOV` 再算一遍 —— 算第二遍一定会漂。

⚠️ **前提是画布不卸载**，见 `05-TECH_ARCHITECTURE.md` §6.1。

## 12. 无障碍与降级

- 全部操作必须可用键盘完成（Tab 遍历、Enter 进入、方向键沿轴移动）
- `prefers-reduced-motion` 时：镜头推进改为直接切换，不做动画
- Low / Minimal 档：缩略图退化为纯贴图（无边缘粒子），镜头推进时长减半
- 无 WebGL2 时：Album 退化为 Library 列表视图，仍然完整可用
