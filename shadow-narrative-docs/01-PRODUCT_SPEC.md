# Shadow Narrative — Product Specification

## 1. 产品定位

Shadow Narrative 是一个面向个人照片与生活记忆的沉浸式数字记忆空间。

它解决的问题不是“如何存照片”，而是：

> **如何让被保存的照片重新变成可以被探索、理解、回忆和讲述的记忆。**

## 2. 用户价值

用户能够：

- 保存照片与媒体
- 将照片组织为 Memory
- 以粒子方式探索照片
- 在空间中浏览过去的记忆
- 与 AI 讨论照片和记忆
- 将碎片整理成随笔小记/故事
- 再次进入已经保存的记忆

## 3. 设计人格

产品人格：

- 安静
- 克制
- 温柔
- 细腻
- 有空间感
- 有一点神秘
- 不喧闹
- 不游戏化

## 4. 核心对象：Photo（照片）

**照片是主实体，不是记忆的附属。**

每一次上传生成一张独立的 Photo。它自带文件、时间、AI 理解、对话和随笔小记。
用户可以像用相册一样把若干张照片归到一册 Memory（影册），但**这是可选的**
—— 不归册不影响任何功能。

```text
Photo
├── 文件（原图 / 缩略图）
├── 尺寸 · 大小 · 拍摄时间（EXIF）
├── favorite          收藏 → 出现在斜轴相册
├── caption           用户自己写的说明（可选）
├── AI understanding  看图结果，按 Observed / Inferred 分级
├── conversation      字幕（第一条）+ 之后的对话
└── journal           整理好的随笔小记（可选）
```

### Memory 是可选的影册，不是容器

```text
Memory
├── title         名字。**必填** —— 架子上那一格读的就是它
└── photos[]      多对多：一张照片可以同时属于多个影册
```

> ⚠️ **2026-10-11 砍到只剩 `title`。** `summary` 与 `memoryDate` 删了：
> 前者是给 Memory Theater 准备的，而 Theater 当天被用户标为**待定**
> （「有待商榷，暂时不知道作用和实现效果」），没有写入者；后者是
> 「Memory = 一次事件」那个已废弃模型的遗物 —— 一册「猫」没有某一天。
>
> 与删 `UserSettings.autoAnalyze`、`Journal.title` / `status` 同一条理由：
> **恒不写入的列会让下一个人以为它坏了。** Theater 定下来时再加回来，
> 加列是增量的。

**为什么是「可选」**：AI 在每张照片上传时就独立开口，本来就不需要一个容器当前提。
把照片降级成「记忆的一部分」会让「这张照片的对话挂在哪」变成一个没有答案的问题。

### 一句话对比

| | 改之前 | 改之后 |
|---|---|---|
| 主实体 | Memory | **Photo** |
| 照片的角色 | 记忆的一部分 | **独立实体** |
| 影册的角色 | 必须 | **可选，像相册** |
| AI 开口时机 | 整理记忆时 | **上传即开口** |
| 收藏粒度 | — | **照片** |

## 5. 核心空间

产品是 **7 个体验状态**，不是 7 个割裂的页面：

| 空间 | 作用 | 入口 |
|---|---|---|
| **Album** | 收藏的照片沿一条斜轴排布在 3D 空间里 | **第一屏** |
| **Photo View** | 看一张照片。默认原图，可切换粒子 | 点相册里的照片 |
| **Photo Particle** | 照片粒子化后的交互状态 | Photo View 里点「Into this moment」 |
| **Conversation** | 字幕 + 对话 | 照片下方 |
| **Journal** | 沉浸式文字阅读 / 编辑 | 用户主动触发 |
| **时间线** | 全部照片，按天挂在中央时间线上 | 顶栏「Timeline」 |
| **Memories** | 影册的架子，打开一册看里面的照片 | 顶栏「Memories」 |

详细规格见 `16-ALBUM_SPACE.md`（影册见 `07-UI_PAGE_SPECS.md` §12）。

> ⚠️ **2026-10-11：第 7 项由「Memory Theater」换成了「Memories」。**
>
> 用户当天定的第三个空间：**影册** —— 「现在的图片是单张的，时间线是根据
> 时间来分的，**分组则是用户自己分**，就像相册一样使用」。于是三个空间各切
> 一刀：Album 是「我挑出来的」（收藏）、时间线是「我拍过的全部」（按天）、
> **影册是「我自己归的」**。
>
> ⚠️ **Memory Theater 标为待定，没有取消。** 用户当天的话是「**有待商榷，
> 暂时不知道作用和实现效果**」—— `07 §6` 那一段留着，别删，也先别做。
>
> ⚠️ 同一天还**排除**了一项：`/memories` 不做成 iOS 那种「全部照片库」。
> 用户自己收回了 —— 「那就不做全部照片了，**保留原本的时间线**」。
> 时间线已经在讲「全部照片」，两个空间做同一件事在这个产品里一向是合并
> （Library 抽屉就是这么被时间线取代的）。

> ⚠️ **2026-10-10：第 6 项由「Library 抽屉」改成了「时间线」。**
> 用户当日定的新空间，**取代** Library，不并存。理由：抽屉里放不下
> 「一天」这个刻度 —— 而那正是个人相册里最自然的单位。
>
> 它同时把上面这棵树从**嵌套**变成了**并列**：Library 原先长在 Album 里面
> （左侧抽屉），时间线是自己的一条路由，和 Album 平级。见 `16 §1`。
>
> 这两者分工是清楚的：**Album 是"我挑出来的"，时间线是"我拍过的全部"。**

### 设置不在这 7 个状态里

设置（`07-UI_PAGE_SPECS.md` §11）是体验**之外**的配置层，刻意不放进上面这张表。

它不是记忆的一部分 —— 用户离开体验去改配置，本来就是有意识的行为，
所以「不能让人感觉是切换页面」那条约束不适用于它。

但反过来说：**不要把设置的入口混进照片旁边。** 它只有一处入口 ——
左下角一颗常驻的悬浮球。

> ⚠️ **2026-10-10：它不是一个页面了，是一张浮卡。**
> 用户要求「设置做成组件，不用单页，用一个齿轮图标放到左下角悬浮」，
> 并指定照 Next.js 左下角那颗开发球做。
>
> 所以本文档里**再没有任何一处允许长成普通页面**了 ——
> 所有界面都在同一块画布上（`05 §6.1`）。

### 关于 Memory Field 的说明

原设计里有一个 Memory Field（「探索所有 Memory 的空间」）。斜轴相册加上时间线
之后，**它在功能上已经重复**——两者都是「在空间里浏览很多记忆」。
本项目暂时不做 Memory Field，等真出现它才能满足的需求时再重新考虑。

## 6. 主要用户流程

### 上传一张照片

```text
拖入照片
    ↓
立刻原图成型（不等网络往返）
    ↓
后台发给 AI
    ↓
字幕浮现 —— AI 的第一句话        ← 记忆在这里诞生
    ↓
可以接着聊
    ↓
（可选）收藏 → 进入斜轴相册
    ↓
（可选）归入某一册
```

### 从斜轴相册进入某张照片

```text
Album（斜轴，收藏的照片）
    ↓
拖拽 / 滚动沿轴移动，焦点落在某张
    ↓
点击
    ↓
相机推进，丝滑过渡
    ↓
Photo View —— 默认原图模式
    ↓
点「Into this moment」
    ↓
原图 → 粒子，无缝切换
    ↓
（可选）展开对话 / 写随笔小记
```

### 找回没收藏的照片

```text
左侧抽屉展开
    ↓
按时间的纯文字列表（不是平铺网格）
    ↓
点某一条 → Photo View
```

### 整理

```text
Photo View
    ↓
对话聊过一些
    ↓
用户主动点「整理成随笔小记」
    ↓
AI 起草，用户定稿
    ↓
随笔小记留在照片上，随时可读
```

## 7. MVP 必须完成

- 照片上传（拖入 + 点击选择）
- 原图 ⇄ 粒子的双向切换
- Photo → Particle / Particle Morph
- Particle interaction
- **斜轴相册**（收藏的照片）
- **Photo View**（默认原图模式）
- 左侧抽屉 Library
- 字幕 + AI 对话
- 随笔小记阅读与生成
- 收藏
- 本地 SQLite 持久化
- Mobile 基础适配

## 8. 明确不做的方向

以下内容不属于 Shadow Narrative 产品范围，不应在任何开发阶段主动加入：

- 支付
- 订阅
- 会员体系
- 商业套餐
- 广告与广告位
- 电商与交易
- 企业售卖功能
- 多租户商业化架构
- 计费、发票、订单系统
- 变现或商业推广机制

此外，社交、公开分享、推荐算法、多人协作、复杂后台管理也不属于当前核心范围，除非未来另行明确提出。

## 9. 不允许的产品漂移

**不要把产品的重点改成「AI 自动帮你写随笔小记」。**

随笔小记必须由用户主动触发。AI 可以起草，但「要不要把这段对话收拢成文字」是用户
的决定 —— 这是过程与结果的边界，不能由 AI 代劳。

同样不允许的：**AI 替用户定义这段记忆是什么。** AI 可以观察、可以问，但不能
下结论说「这一定是你最难忘的一天」。

真正主角仍是：

**照片本身 + 粒子 + 沉浸式浏览。**

AI 是辅助能力 —— 一个愿意开口、接得住话的辅助者，但它不拥有这段记忆。

## 10. 成功标准

成功的产品不是功能最多，而是：

> 用户愿意停留、探索、触碰和重新阅读自己的记忆。
